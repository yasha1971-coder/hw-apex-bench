# Adapter qualification (experimental)

On a 64-bit Linux host with Bash, Python 3, Git, GCC/G++, Make and zlib development
headers, run from the checkout:

```sh
./run.sh --check codecs/bgzip.sh
./run.sh --check codecs/zstd_seekable.sh
./run.sh --check codecs/aceapex.sh
```

Sources and the small corpus are fetched automatically at exact SHA/MD5 pins.
Logs and JSON qualification receipts go to `.adapter-work/`; `--work-dir PATH`
selects a separate build directory. A failed check removes its previous receipt.
Build directories are locked against simultaneous checks. Build timeout is 20
minutes; other commands have a two-minute timeout. Timed-out process groups are
terminated. Source modifications or wrong revisions fail rather than being reset.
Adapters are trusted executable build code, not sandboxed plugins.

Each codec is a single shell file; it can embed the native bridge it compiles.
The loader has no list of codec names. Pass any adapter path to `--check`.
Source `harness/adapter_common.sh`, implement the functions below and finish with
`cb_entry "$@"`. See `codecs/zstd_seekable.sh` for a complete source-build example.

| Function | Contract |
|---|---|
| `codec_name`, `codec_version` | One nonempty line each; must match native metadata |
| `codec_build` | Build pinned sources and shared library; nonzero on failure |
| `codec_compress IN OUT G` | Untimed archive preparation; G is bytes |
| `codec_decompress IN OUT` | Untimed byte-exact restoration |
| `codec_region ARC OFFSET LENGTH OUT` | Untimed wrapper around native region API |
| `codec_supports` | Space-separated capability names from `harness/adapter_api.h` |
| `codec_unavailable` | JSON map containing a nonempty reason for every absent capability |
| `codec_library` | Absolute shared-library path |
| `codec_sources` | JSON array of `{url, sha, directory}`; full 40-character Git pins |
| `codec_artifacts ARC` | JSON array of archive and every required sidecar; sibling files |
| `codec_constraints` | JSON with `min_input_bytes`, `min_input_reason`, `granularity` |

The shared library exports `cabench_adapter_v1()` with the versioned callback table
in `harness/adapter_api.h`. Shell functions never belong inside performance timers.
The native `open` callback receives only the archive path and an output-size limit;
region callbacks receive offsets and lengths. Index opening/allocation is outside
future region timers. This ABI currently targets Linux, a 64-bit process and
little-endian upstream archive layouts. Archive/input reads are capped at 1 GiB
for qualification. This is not a security certification or a general archive fuzzer.

The check downloads the pinned corpus in `corpora.json`, adds deterministic binary
and DNA fixtures, a one-byte case and an empty case where supported. It moves only
declared archive files to a new directory, verifies full restore and 208 region
calls per case (including edges and invalid ranges), checks output-buffer guards,
and checks native batch results where offered. Restores through the public shell
functions are also compared byte for byte. A receipt records dependency SHAs,
submodules, compiler, adapter/library/worker hashes, capabilities and checks.

Capability availability does not prove the entire measurement protocol. There are
no timers or performance numbers in these receipts. The historical full benchmark
still uses its recorded harness; `./run.sh` without arguments still invokes that
harness. The next gate is moving measurement scheduling and normalized JSONL output
onto this ABI without losing plateau, counter or same-run-baseline checks. Existing
historical measurements and publication files are not regenerated by `--check`.
Do not add a codec to the published table merely because qualification passed.

Current limitations:

- HTSlib is pinned to 1.24 with a minimal zlib-only build. Historical measurements
  used their own recorded versions; these new binaries do not replace those numbers.
- BGZF has no native batch API or arbitrary one-block baseline above its format limit.
- Zstd-seekable has no native batch API. It uses the contrib seekable library API.
- Amplification instrumentation remains in the historical harness. Until ported and
  independently validated, every new adapter reports it unavailable.
- ACEAPEX a194893 one-shot compression writes the compile-time 1 MiB block size even
  with `ACEAPEX_BS=16384`. A 262400-byte input produced 17 blocks with a 1 MiB header.
  This adapter uses the unchanged original CLI for untimed preparation; native
  encode is unavailable. Empty inputs are explicitly unsupported. Native full
  decode uses eight internal workers; batch requests one worker. These are distinct
  scopes, not equal-thread performance claims.

Automatic CI runs only small correctness checks and publication validation. Full
benchmark, audit and curve workflows require manual dispatch. xz, CRAM, portable
native timing, unified measurement JSONL, licensing and release/DOI remain separate
gates. Ratios to a baseline measured in the same run improve comparisons but do
not make hardware differences disappear. CRAM needs alignment-specific semantics;
lossy quality quantization must never be assumed to be its default behavior.
